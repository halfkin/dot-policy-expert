# Incident Response Policy (Internal)

## P1 Incident Definition and Response Time
**P1 (Critical)** incidents mean core functionality is down for all users. Required response time is **15 minutes**.

## P2 Incident Definition and Response Time
**P2 (High)** incidents mean a major feature is broken with no workaround. Required response time is **60 minutes**.

## P3 Incident Definition and Response Time
**P3 (Medium)** incidents mean a minor bug exists and a workaround is available. Required response time is **8 hours**.

## P4 Incident Definition and Response Time
**P4 (Low)** incidents include UI/UX polish issues and typos. Required response time is **48 hours**.

## Post-Mortem Requirement for P1 and P2
A post-mortem is required for all **P1 and P2** incidents. The post-mortem must be completed within **72 hours** of resolution.

## P1 Escalation to CTO
If a **P1** incident is not resolved within **4 hours**, the **CTO must be paged directly**. This escalation applies specifically to unresolved P1 incidents at the 4-hour mark.
